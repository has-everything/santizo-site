# santizo-site: santizo.com, version B

The editorial redesign of santizo.com for Hector Augusto Santizo (HAS): full-screen reel, featured work, XR strip, apps, contact; a Work page with a page per video (15), plus one-off pages for HAS Toyline (a 3D assembly line and its money layer, not public as an app) HAS Space (a desktop interior design studio in beta) and HAS Records (a turntable you can play, in Unreal Engine); an Apps page (five has.tools apps, each with its own page here: HAS Lathe, Splay, HAS Sculpt, HAS Truss, HAS Gallery; plus HAS Space, whose card opens its work page); a Burning Man page (photos); and an Info page (about, expertise, how I work).

**Live on santizo.com since October 2026.** It was built as version B alongside the previous site, SantizoOS (version A, repo `has-everything/santizo-os`), which now lives on at `https://santizo-os.vercel.app` and is linked from the footer as "OS mode". Both are separate Vercel projects; santizo.com and www belong to this one. **www.santizo.com is the primary address** (Vercel's default, as it was for SantizoOS): santizo.com 308-redirects to it, and `site` in `astro.config.mjs` is `https://www.santizo.com`, so every canonical URL, link preview, JSON-LD URL and the sitemap use www.

Built with Astro (static output, no client framework). The build ships plain HTML and CSS plus one small script. The design source is the owner's two HTML mockups (`index.html` and `has-lathe.html`, October 2026). This build was checked pixel-identical to them at 1440px and 390px wide, in day and night themes. Since then the layout was widened (see Wide layout under Conventions), and the top bar and the Play reel button come from the owner's XK variant mockup (`index-xk.html`): a fixed bar (Work, Apps, Info) that inverts over what is behind it, a quieter Play reel link, and the ruled Apps list.

## Common tasks

**Add a video project**: add an entry to `projects` in `src/data/work.ts` (`slug` becomes `/work/<slug>`; `video` is `{ vimeo: id }` or `{ youtube: id }`). It appears on `/work` in its group and gets its own page automatically. Give it the owner's write-up as `tagline` (shown under the title instead of the blurb) and `story` (sections like `{ title: 'Vision', paras: ['...'] }`, rendered by `Story`), and a `year`; each shows only when set. Van Gogh · The Bedroom and HAS LP-19 have write-ups (the owner's, Oct 2026, tightened in the same edit pass), and so do HAS Photo Booth and Hand Tracker (the owner's text, Oct 2026, set in story sections with his wording kept: lists became paragraphs, the one em dash a new sentence; neither has a tagline, so the blurb shows): the owner writes them, so never invent stories, years, clients or credits.

**Add photos**: save as WebP in `public/img/photos/` and add `{ src, w, h, alt }` to `src/data/photos.ts` (w/h are the real pixel size: they reserve each photo's space before it loads). Every photo shows at the same width, up to 1200px, so export new ones at least 1200px wide or they get upscaled; larger exports would look sharper on big retina screens.

**Add or reorder featured work**: edit `featured` in `src/data/work.ts`. The first item runs full width; the rest pair up in rows that alternate wide/narrow and narrow/wide, and a last one on its own runs full width. An app joins by title with `app('Splay')` (its Apps card, tagged Free app).

**Give a project a self-hosted tile loop**: cut its video to about 8 s at 1280x720, H.264, no sound, `-movflags +faststart` (so it plays while it downloads), as `public/video/<slug>-tile.mp4`, with its first frame as `public/img/work/<slug>/tile-poster.webp`; then add `tile: loop('<slug>')` to the project in `src/data/work.ts`. For any other item, set `media` to `{ video: '/video/name.mp4', poster: '/img/name.webp' }`. `*.mp4` is gitignored by default (mirrors santizo-os), so commit clips with `git add -f`.

**Change the apps on /apps**: edit `tools` in `src/data/apps.ts` (grid order, three across on wide screens; a half-empty last row is fine, owner's call). Card images are the has.tools stage captures (`has-tools-website/img/<slug>-stage.png`, 2400x1350) saved as 2000px WebP in `public/img/apps/<slug>.webp`. Each card opens the app's page here (`/apps/<slug>`); the page's "Open … ↗" button goes to the app on has.tools. On the site (owner's pick and order, Oct 2026): Splay, HAS Lathe, HAS Space, HAS Truss, HAS Gallery, HAS Sculpt (HAS Space is not on has.tools: a desktop app in beta, its card opens its case study). Left out: HAS Cabinet, HAS Books, HAS Dither and PLAT (removed by the owner), and HAS Frame Extract and HAS Frames (2D utilities, weakest fit for a 3D motion portfolio).

**Add an app page**: add an entry to `appPages` in `src/data/app-pages.ts` (its position sets its place in the list), put its images in `public/img/apps/<app>/` and a 1200x630 preview in `public/img/og/`, then add the card to `tools` in `src/data/apps.ts` with `href: '/apps/<slug>'`. The page and its sitemap entry are generated.

**Change the XR clips on the home page**: the home XR section shows three wide clips in a row (one per row on phones); pick them by slug in `xr.clips` in `src/data/work.ts` (currently Wrist Interaction, 3D Calculator and Pinch Twist: Vimeo loops that match the statement). Its "All XR →" opens `/work#xr`.

**Change the XR intro**: `xrIntro` in `src/data/work.ts`, shown at the top of /work's XR and interaction section. `lead` and `body` were written from the owner's placeholder (his tools list is verbatim). It was the XR page, `/xr`, until Oct 2026, when the owner folded it into /work (all its projects were there already): `/xr` redirects to `/work#xr` (`redirects` in `astro.config.mjs`, like `/photos`). A new XR project goes in `projects` with group `xr`.

**Add a one-off project page**: build it from `src/pages/apps/[slug].astro` and its parts (its path is its URL): copy, figures, `description`, preview `image` and `schema`; add its path to `src/pages/sitemap.xml.ts`, then point the work item's `href` at it.

## Conventions

- **No em dashes** anywhere in copy. Use commas, colons, or the middot ` · `.
- **Layout** (matched to field.io, owner's call, Oct 2026): heroes at the top of a page run the full window width (the home reel, each project's film band, the app and case-study hero images: they sit outside `.wrap`). Everything else sits in a centred column whose side margins are `--margin`: 4.32vw from 760px up (83px at 1920), the thin `--gutter` on phones. Tiles sit `--tile-gap: 13px` apart. The owner measured field.io at three images of 576px with 13px between them, so the column stops at 1754px (`--max: calc(1754px + 2 * var(--margin))`): at 1920 three across are exactly 576px each, and bigger screens get wider margins, not bigger tiles. History: edge to edge everywhere first (too wide below the hero), then an 82vw / 1440px column (narrower than field.io), then this. The top bar and the crumbs stay at the page edges, with the heroes. Media grids use `.grid-2` / `.grid-3` (fixed column counts). Text keeps its own `ch` reading widths. Project videos sit edge to edge on a band in the page's color (white by day; it was black until the owner asked for white, Oct 2026), sized to fit the screen under the top bar. Burning Man photos stay capped at 1200px (their real size).
- **Prefer simple over optimal**: no extra config, infra, or dependencies unless there is a user-visible problem.
- Theme: day by default; `?theme=night` in the URL; the footer toggle remembers the choice in `localStorage` under `santizo-theme`.
- **Splay and HAS Lathe on the home page play loops too** (owner's ask, Oct 2026), set on their entries in `featured`, not on their Apps cards. Splay's is its own quadcopter demo exploding, holding and coming back together, made with Splay's Render (no interface); a first try rendered with HAS Explode (the Splay speaker) was turned down by the owner as looking cheap. HAS Lathe's is a vessel on the wheel, turning from vase (celadon glaze) to bottle (terracotta) to bowl (brass), rendered in the app. How to re-render them: `tools/loops/README.md`.
- **Tiles play short loops served from this site** (owner's call, Oct 2026): every Vimeo project has `tile: loop('<slug>')`, an 8 s 720p cut of its video in `public/video/` (the shorter ones whole), because each Vimeo tile loaded its own player (about 350 KB of code, then a stream from three or four hosts; about 1.4 s to a first frame) where a file from Vercel starts in about 0.15 s. Cuts taken from the middle of a video end in a 0.5 s crossfade into their first frame, so the loop has no jump; square and vertical videos keep black side bars, as Vimeo showed them. A tile clip has `preload="none"` and its poster is a lazy `<img>` behind it: `src/scripts/lazy-video.ts` plays it as it comes within a screen of view and pauses it a screen away. A project without `tile` falls back to its Vimeo clip as a muted background loop (`background=1`, `loading="lazy"`). The home reel stays a Vimeo embed, eager (`lazy={false}` on `Media`), because Play reel plays the whole reel with sound; the HAS Toyline film is also `lazy={false}`. YouTube videos show as their thumbnail. Every tile opens its project page on this site, where `VideoPlayer` plays the Vimeo or YouTube video with sound and controls.
- **Play reel stays on the site**: it restarts the reel from the top with sound and the button becomes Stop; Stop, the end of the reel, or scrolling away returns to the silent loop. Two drivers in `src/scripts/reel.ts`:
  - Vimeo loop (default): unmuted through the Player API, lazy-loaded `@vimeo/player`. Works in desktop browsers (owner-tested). iPhones and iPads refuse sound started from the page on a cross-origin embed, so there Play reel stays a plain link to the reel's own page (`reel.href`, `/work/santizo-reel-2026`), where it plays with sound and controls. A desktop browser that rejects play() is sent there too; one that pauses the unmuted video just returns to the silent loop.
  - Direct file: when `reel.file` in `src/data/site.ts` holds an MP4 of the reel (Vimeo: video settings, ⋯ menu, Video file links, Copy link), the hero plays it in a plain `<video>` and sound works everywhere, iPhones included.
- **No black screen while the reel loads** (owner's ask, Oct 2026): until the Vimeo loop plays, the hero shows a still of it (`reel.poster`, `public/img/reel-poster.webp`, the reel half a second in, since its first frames are blank) and an orange loading line sweeping along its bottom edge. `reel.ts` fades both out once Vimeo reports the reel past 0.5 s, so the still hands off to the same frame. If Vimeo never plays, the still stays and the line stops after 20 s. Without JavaScript neither shows. Re-export the still if the reel's opening changes.
- **Never show Vimeo's controls** on the hero (owner's call), and don't add timers or checks that swap the player: an earlier 6-second check misfired on a working embed and restarted the reel.
- The end of the reel is detected from `timeupdate` jumping back to the start, because background embeds loop.
- Top bar: Work (`/work`), Apps (`/apps`), Burning Man (`/burning-man`), Info (`/info`); XR left it in Oct 2026, with the XR page. Measured to stay on one line, inside the right margin, at every width from 320px up: labels never wrap, gaps tighten below 400px, the text drops to 14px below 375px and to 13px below 351px. Four links leave a little room on small phones; check 320px before adding a fifth. The bar sits inset from the media edges (gutter plus 0 to 24px, growing with screen width) so the logo and menu don't line up flush with the videos. It has no background, by design: page content scrolls under it.

## Deploy

Vercel project imported from this GitHub repo, Framework Preset **Astro**, all defaults (build `astro build`, output `dist`). Push to `main` = production; any other branch gets its own preview URL, `https://santizo-site-git-<branch>-augustos-projects-c42fb8a3.vercel.app`. Keep preview branch names to 18 characters or fewer (e.g. `has-space`): that host name part can't pass 63 characters, and past it Vercel shortens the name with a hash, so the predictable address doesn't exist (as happened with `has-space-case-study`). santizo-os notes that the GitHub webhook has missed pushes before. If a push doesn't show up, run `vercel deploy --prod` from this folder.

Web Analytics: the snippet is in `Base.astro`. Turn it on in the Vercel project (Analytics tab).
